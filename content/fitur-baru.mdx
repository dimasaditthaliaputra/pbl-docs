## Gambaran Umum

Setiap penambahan fitur atau modul baru di lingkungan proyek PAGORA wajib mengikuti alur rekayasa terstruktur dari lapisan data paling bawah hingga antarmuka pengguna. Standar ini memastikan bahwa model database, kontrak antarmuka, logika bisnis, validasi, dan rendering React selalu sinkron dan teruji.

<Callout type="info" title="Urutan Eksekusi Wajib">
  Pengerjaan fitur selalu mengalir dari layer terbawah menuju antarmuka:
  <strong>
    Migration/Model → Repository → Service → Form Request → API Resource → Controller → Route →
    Frontend.
  </strong>
</Callout>

## 1. Urutan Pengerjaan Fitur Baru (11 Tahap)

Ikuti sebelas langkah berikut secara berurutan saat menambahkan modul baru:

<Steps>
  <Step title="1. Pahami Alur Fitur & Tulis Asumsi">
    <p>
      Pelajari alur bisnis fitur yang diminta. Jika menemukan hal yang ambigu atau belum terdefinisi secara jelas pada spesifikasi, tuliskan sebagai poin asumsi teknis sebelum mulai menulis kode.
    </p>
  </Step>

<Step title="2. Periksa & Gunakan Ulang Kode yang Ada">
  <p>
    Periksa model, migration, komponen antarmuka, dan helper yang sudah ada di dalam proyek. Gunakan
    kembali kode yang tersedia dan hindari membuat fungsi atau komponen duplikat.
  </p>
</Step>

  <Step title="3. Buat Migration & Model dengan UUID">
    <p>
      Buat migration database baru dengan kolom UUID publik <code>$table->uuid('uuid')->unique()</code>. Pada Model Eloquent, pasang trait <code>HasUuids</code>, sembunyikan id internal dengan <code>$hidden = ['id']</code>, dan setel <code>getRouteKeyName()</code> ke <code>'uuid'</code>.
    </p>
  </Step>

<Step title="4. Buat Repository Interface & Implementasi">
  <p>
    Definisikan kontrak query di{' '}
    <code>{'app/Repositories/Contracts/{Model}RepositoryInterface.php'}</code>. Buat implementasi
    query Eloquent di <code>{'app/Repositories/Eloquent/{Model}Repository.php'}</code> dengan
    whitelist kolom sort dan paginasi maksimal 100 baris. Daftarkan binding di{' '}
    <code>RepositoryServiceProvider.php</code>.
  </p>
</Step>

<Step title="5. Buat Service & Transaksi">
  <p>
    Pusatkan logika bisnis di <code>{'app/Services/{Model}Service.php'}</code>. Suntikkan Repository
    Interface melalui constructor. Bungkus operasi yang menyentuh lebih dari satu tabel dalam blok
    transaksi <code>DB::transaction()</code>.
  </p>
</Step>

<Step title="6. Buat Form Request dengan Pesan Indonesia">
  <p>
    Buat Form Request terpisah di <code>{'app/Http/Requests/{Domain}/'}</code> (contoh:{' '}
    <code>StoreKomoditasRequest.php</code>). Seluruh pesan kegagalan validasi pada method{' '}
    <code>messages()</code> wajib menggunakan Bahasa Indonesia.
  </p>
</Step>

<Step title="7. Buat API Resource Eksplisit">
  <p>
    Buat Resource di <code>{'app/Http/Resources/{Model}Resource.php'}</code> untuk memetakan data
    model menjadi representasi yang siap dikonsumsi frontend. Pastikan kolom internal{' '}
    <code>id</code> tidak pernah disertakan.
  </p>
</Step>

<Step title="8. Buat Controller Tipis">
  <p>
    Buat controller tipis di <code>app/Http/Controllers/</code>. Controller hanya memanggil method
    pada Service dan membungkus hasil respons via <code>ResponseHelper</code> atau{' '}
    <code>Inertia::render()</code>.
  </p>
</Step>

<Step title="9. Daftarkan Route Web">
  <p>
    Daftarkan route di <code>routes/web.php</code>. Berikan parameter <code>{'{uuid}'}</code> dengan
    constraint <code>whereUuid('uuid')</code>. Seluruh rute wajib memiliki nama (<code>name()</code>
    ) dan middleware yang sesuai (<code>auth</code> atau <code>guest</code>).
  </p>
</Step>

<Step title="10. Bangun Antarmuka React di Pages/">
  <p>
    Buat komponen halaman di <code>{'Pages/Master/{Modul}/'}</code> yang terdiri dari{' '}
    <code>Index.jsx</code> (tabel data TanStack server-side), <code>Create.jsx</code>,{' '}
    <code>Edit.jsx</code>, <code>{'{Modul}Form.jsx'}</code> (form bersama), dan{' '}
    <code>columns.jsx</code> (definisi kolom).
  </p>
</Step>

  <Step title="11. Jalankan Verifikasi Pra-Selesai">
    <p>
      Jalankan perintah verifikasi: pastikan <code>php artisan route:list</code> tidak memiliki konflik rute, serta perintah <code>npm run build</code> dan <code>npm run lint</code> selesai tanpa error.
    </p>
  </Step>
</Steps>

## 3. Format Laporan Akhir (Untuk AI Agent)

Setiap AI agent yang menyelesaikan implementasi fitur baru diwajibkan menyajikan laporan terstruktur dengan format:

1. **Asumsi** (jika ada hal yang ambigu pada kebutuhan fitur)
2. **Daftar File:** dibuat / diubah / dihapus
3. **Kode Lengkap / Ringkasan Implementasi**
4. **Perintah yang Perlu Dijalankan** (misal: `php artisan migrate`, `npm install`, dst.)
5. **Hasil Verifikasi** (bukti lolos lint, route check, dan build)
