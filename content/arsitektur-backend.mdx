## Gambaran Umum

Backend PAGORA mengombinasikan pola **Model-View-Controller (MVC)** dengan **Service Repository Pattern**. Arsitektur ini bertujuan menjaga Controller tetap tipis (_thin controller_), memusatkan logika bisnis dan integritas transaksi di layer Service, serta memisahkan akses database melalui Repository Interface.

## 1. Alur Request

Alur request mengalir secara linier dari layer terluar menuju penyimpanan data, dan kembali menyajikan respon ke pengguna:

```
Route → Controller → Service → Repository (Interface) → Model → Database
```

Respon kembali melalui jalur yang sama: Model mengembalikan data ke Repository, Service memproses atau mentransformasikannya, dan Controller membungkus respon melalui `ResponseHelper` atau `Inertia::render()`.

## 2. Tanggung Jawab Tiap Layer

Setiap layer memiliki batasan dan tanggung jawab yang tegas:

| Layer            | Boleh Dilakukan                                                                        | Dilarang Keras                                                           |
| ---------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **Route**        | Memetakan URL ke method controller, memasang middleware, memberi `name()`              | `return view()`, `Inertia::render()`, `Route::inertia()`, closure logika |
| **Controller**   | Menerima request, memanggil Service, return via `ResponseHelper` / `Inertia::render`   | Query Eloquent langsung, logika bisnis, validasi inline                  |
| **Form Request** | Aturan validasi input, pesan error Bahasa Indonesia (`messages()`), otorisasi          | Menjalankan logika bisnis atau transaksi database                        |
| **Service**      | Logika bisnis, orkestrasi beberapa repository, `DB::transaction()`, melempar exception | Mengakses objek `Request`, return response HTTP, query Eloquent langsung |
| **Repository**   | Akses data (query Eloquent), eager loading (`with()`), paginate, filter                | Logika bisnis, return response HTTP                                      |
| **Model**        | Relasi, `casts()`, `$fillable`, `$hidden = ['id']`, scope query, accessor              | Logika bisnis kompleks atau manipulasi data multi-tabel                  |

<Callout type="danger" title="Larangan Keras pada Layer Controller & Service">
  <ul>
    <li>
      Dilarang menuliskan query Eloquent (seperti <code>Komoditas::where(...)</code>) di dalam
      Controller. Seluruh akses database wajib melalui Repository.
    </li>
    <li>
      Dilarang mengembalikan response HTTP atau objek <code>Request</code> dari dalam Service.
      Service murni mengembalikan entitas Model, koleksi data, atau melempar Exception.
    </li>
  </ul>
</Callout>

## 3. Aturan Dependency

Penerapan Service Repository Pattern di PAGORA mengikuti aturan ketergantungan berikut:

- Controller meng-inject **Service** melalui constructor.
- Service meng-inject **Repository Interface** (bukan class konkret Eloquent) melalui constructor.
- Binding antara interface dan implementasi konkret didaftarkan di `RepositoryServiceProvider`, yang didaftarkan pada `bootstrap/providers.php`.
- **Satu Repository untuk satu Model.**
- **Satu Service untuk satu domain fitur** (diperbolehkan memanggil Service lain jika membutuhkan operasi lintas domain).
- **Satu Controller per domain.** Method yang me-render halaman dipisahkan dari method yang memproses aksi (contoh: `login()` untuk halaman login vs `storeAuth()` untuk memproses submit form).

declare(strict_types=1);

namespace App\\Repositories\\Eloquent;

use App\\Models\\Komoditas;
use App\\Repositories\\Contracts\\KomoditasRepositoryInterface;
use Illuminate\\Pagination\\LengthAwarePaginator;

class KomoditasRepository implements KomoditasRepositoryInterface
{
private const SORTABLE = ['name', 'created_at']; // whitelist kolom sort

    public function __construct(private readonly Komoditas $model) {}

    public function paginate(array $filters, int $perPage = 10): LengthAwarePaginator
    {
        $sort = in_array($filters['sort'] ?? null, self::SORTABLE, true)
            ? $filters['sort']
            : 'created_at';
        $direction = ($filters['direction'] ?? 'desc') === 'asc' ? 'asc' : 'desc';

        return $this->model
            ->when($filters['search'] ?? null, fn ($q, $s) => $q->where('name', 'like', "%{$s}%"))
            ->orderBy($sort, $direction)
            ->paginate(min($perPage, 100))
            ->withQueryString();
    }

    public function findByUuid(string $uuid): ?Komoditas
    {
        return $this->model->where('uuid', $uuid)->first();
    }

    public function create(array $data): Komoditas
    {
        return $this->model->create($data);
    }

    public function update(Komoditas $komoditas, array $data): Komoditas
    {
        $komoditas->update($data);
        return $komoditas->fresh();
    }

    public function delete(Komoditas $komoditas): void
    {
        $komoditas->delete();
    }

}`}
/>

namespace App\\Services;

use App\\Models\\Komoditas;

use Illuminate\\Database\\Eloquent\\ModelNotFoundException;
use Illuminate\\Pagination\\LengthAwarePaginator;
use Illuminate\\Support\\Facades\\DB;

class KomoditasService
{
public function \_\_construct(
private readonly KomoditasRepositoryInterface $komoditas
) {}

    public function paginate(array $filters, int $perPage = 10): LengthAwarePaginator
    {
        return $this->komoditas->paginate($filters, $perPage);
    }

    public function findByUuid(string $uuid): Komoditas
    {
        return $this->komoditas->findByUuid($uuid)
            ?? throw new ModelNotFoundException('Data tidak ditemukan.');
    }

    public function store(array $data): Komoditas
    {
        // Operasi yang menyentuh lebih dari satu tabel dibungkus DB::transaction() di sini
        return DB::transaction(fn () => $this->komoditas->create($data));
    }

}`}

## 5. Standar Routing

Routing didefinisikan dengan pengelompokan yang rapi di `routes/web.php`:

<CodeBlock
  filename="routes/web.php"
  language="php"
  illustration={true}
  code={`Route::controller(KomoditasController::class)
    ->prefix('komoditas')
    ->name('komoditas.')
    ->middleware('auth')
    ->group(function () {
        Route::get('/', 'index')->name('index');
        Route::get('/create', 'create')->name('create');
        Route::post('/', 'store')->name('store');
        Route::get('/{uuid}/edit', 'edit')->whereUuid('uuid')->name('edit');
        Route::put('/{uuid}', 'update')->whereUuid('uuid')->name('update');
        Route::delete('/{uuid}', 'destroy')->whereUuid('uuid')->name('destroy');
    });`}
/>

Aturan routing:

- Semua route menunjuk ke method controller dan wajib memiliki `name()`.
- Kelompokkan menggunakan `Route::middleware(...)->group(...)` dan `Route::controller(...)->group(...)`.
- Middleware: `guest` untuk login/register/Google OAuth; `auth` untuk logout dan dashboard terproteksi.
- Parameter resource **wajib `{uuid}` atau `{slug}`**, dengan constraint `whereUuid('uuid')` atau `where()`. **Dilarang memakai `{id}`**.
- **Tidak memakai implicit route model binding.** Controller menerima `string $uuid` lalu meneruskannya ke Service, menjaga konsistensi alur Controller → Service → Repository.
- Jika route bawaan Fortify bentrok, nonaktifkan view dengan `Fortify::ignoreRoutes()` dan `'views' => false` pada `config/fortify.php`.

## 6. Identifier Publik: UUID (WAJIB)

Tujuan utama kebijakan ini adalah **mencegah enumerasi data dan eksploitasi IDOR** (_Insecure Direct Object Reference_):

- Kolom `id` auto-increment hanya dipakai **internal backend** untuk keperluan relasi dan _foreign key join_.
- Kolom `id` tidak boleh bocor ke frontend dalam bentuk apa pun: URL, props Inertia, JSON, atribut HTML, form input, hidden field, `key` list, maupun query string.
- Identifier publik default adalah `uuid`, dan opsional `slug` untuk konten publik.
- **UUID bukan pengganti otorisasi.** Policy/Gate dan pemeriksaan kepemilikan data tetap wajib diterapkan pada setiap method aksi.

## 7. Response Helper

Semua controller wajib memakai `App\Helpers\ResponseHelper`. Dilarang memanggil `response()->json(..., 200)` atau `abort(500)` langsung dari controller:

| Method              | Status Code | Kegunaan                                     |
| ------------------- | ----------- | -------------------------------------------- |
| `success()`         | 200         | Operasi berhasil (tampil data, ubah data)    |
| `created()`         | 201         | Berhasil membuat entitas baru                |
| `badRequest()`      | 400         | Request tidak valid / malformed              |
| `unauthorized()`    | 401         | Pengguna belum terautentikasi                |
| `forbidden()`       | 403         | Tidak memiliki hak akses (Policy/Gate gagal) |
| `notFound()`        | 404         | Data tidak ditemukan                         |
| `validationError()` | 422         | Gagal validasi input form                    |
| `serverError()`     | 500         | Kesalahan internal server (wajib Log::error) |

Format JSON seragam:

<CodeBlock
  filename="Format Response JSON"
  language="json"
  code={`{
  "success": true,
  "message": "Pesan untuk user",
  "data": null,
  "errors": null
}`}
/>

Perilaku Response Helper:

- Request dengan `expectsJson()`: Mengembalikan JSON seragam dengan HTTP status code terkait.
- Request Inertia biasa:
  - Sukses: `redirect()->intended($redirectTo)` atau `back()` dengan `->with('success', $message)`.
  - Gagal validasi: `back()->withErrors($errors)` (masuk ke props `errors`, tanpa flash `error`).
  - Gagal non-validasi (400/403/404/500): `back()->with('error', $message)`.
- Flash message dibagikan secara global via `HandleInertiaRequests::share()` dan ditangani satu tempat oleh `flash-handler.jsx`.
- `serverError()` wajib memanggil `Log::error(...)` dan hanya menampilkan pesan generik kepada pengguna demi keamanan.

## 8. Validasi & Form Request

- Seluruh validasi backend wajib menggunakan **Form Request** (`php artisan make:request`), dikelompokkan per domain fitur (contoh: `app/Http/Requests/Komoditas/StoreKomoditasRequest.php`).
- Seluruh pesan error validasi wajib berbahasa Indonesia di dalam method `messages()`.
- Validasi unik (`unique`) atau keberadaan data (`exists`) selalu divalidasi di backend.
- Penamaan Form Request mengikuti konvensi `{Action}{Model}Request` (contoh: `StoreKomoditasRequest`, `UpdateKomoditasRequest`).

## 9. Aturan Database

- Perubahan skema selalu melalui file migration baru; jangan mengedit migration lama yang sudah pernah dijalankan.
- Penamaan tabel: plural `snake_case` (contoh: `komoditas`, `vendors`).
- Foreign key: `{model}_id` via `foreignId()->constrained()` dengan `onDelete` yang jelas.
- Kolom yang sering dicari atau diurutkan wajib memiliki indeks.
- Model wajib mendefinisikan `$fillable` (atau `$guarded` secara sadar) dan `casts()`.
- Operasi database multi-tabel dibungkus `DB::transaction()` di layer **Service**.
- Selalu cegah N+1 query dengan eager loading (`with()`) di layer Repository.

## 10. Autentikasi

- Login email dikelola oleh **Laravel Fortify**; login Google OAuth dikelola oleh **Laravel Socialite**.
- **Login (baik email maupun Google) tidak boleh membuat user baru.** Jika email belum terdaftar, tampilkan error pada input atau tombol login.
- Register (termasuk registrasi vendor) adalah satu-satunya jalur pendaftaran akun baru.
- Setelah login: panggil `session()->regenerate()`. Saat logout: panggil `invalidate()` session dan `regenerateToken()`.
- Password selalu di-hash. Dilarang mencatat password atau kredensial rahasia ke dalam log file.
- Seluruh flow autentikasi dikelola oleh satu controller terpusat: `AuthController.php`.
